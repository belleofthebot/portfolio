the problem

Campaign emails were built by hand every time: source the copy from the product page, rebuild the layout, get it rendering in Outlook, apply the brand system, tag every link correctly for attribution, and remember the compliance opt out. Every step was a place to introduce an error, and the errors were invisible until after send. A mistagged link does not look broken. It just quietly corrupts campaign reporting.

I timed the full manual build at 75 minutes per campaign, measured rather than estimated. On a weekly send that is roughly 65 hours a year spent rebuilding the same layout.

what I built

  • Source copy fetched automatically from a product page URL server side, or from an uploaded sell sheet, so nothing is pasted by hand.
  • The base template lives in the repository and loads every session, so it never has to be re supplied.
  • The brand and technical specification is encoded in the system prompt: 600px table based centred layout, inline CSS only, Outlook desktop rendering via MSO conditional comments and VML bulletproof buttons, no grid or flex, no web fonts, no reliance on background images for critical content, specified colour roles, hidden preheader. This is email development knowledge written down as a machine enforceable standard.
  • UTM tagging enforced on every link, with a documented taxonomy of medium names by element type: header logo, hero image, action CTA, document download, section image, section text link, footer logo, footer link, and social by platform. Mailto links, anchors and merge tags are explicitly exempted.
  • Placeholder tokens instead of invented URLs. Any asset without a final URL gets a named token, listed in a comment block at the top of the file. The model is forbidden from guessing a URL.
  • A self generated audit trail appended to every output: one line per link, with element, destination and tag.

the idea the whole thing is built around

Rather than training people to remember the unsubscribe link and the tagging convention, both were made structurally impossible to omit. The compliance link is not a field someone fills in, it is a server side constant the generator cannot be asked to leave out. The tagging is not a checklist item, it is audited against the actual output, in code, every time.

That is the difference between a process document and a system.

the detail I would want a hiring manager to notice

The audit is deterministic JavaScript parsing the real output HTML. It is not the language model checking its own work. Knowing where AI belongs in a pipeline and where it emphatically does not is a more useful signal than the generator itself.

outcome

  • Campaign email drafted from a product page URL rather than rebuilt from scratch.
  • Opt out compliance cannot be omitted, because omitting it is not a state the system can produce.
  • UTM tagging verified deterministically on every output, so attribution data stops silently degrading.

what I would do differently

Same admission as the deck generator: the tool shipped before the measurement did. I have since timed the manual baseline properly and instrumented the generator, so both halves will exist shortly. The compliance argument never needed a number to stand up, but the time argument does, and I should not have had to go back for it.
